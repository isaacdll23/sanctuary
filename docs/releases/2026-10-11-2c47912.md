## Why

The `11c6eed` dependency upgrade bumped React Router 8.3.0 → 8.4.0, which added
a CSRF guard (`throwIfPotentialCSRFAttack`). It compares the browser's `Origin`
header with the server's own `request.url` origin and returns 400 on mismatch.

Traefik terminates TLS, so the app builds `http://` request URLs while browsers
send an `https://` Origin, so **every** browser form submission (login,
register, reset-password, tasks, notes, finance, …) was rejected with
`400 Bad Request` before reaching its action. Reads were unaffected, so the
GET-based smoke tests did not catch it.

## Fix

`react-router.config.ts` now allowlists the public host:

```ts
allowedActionOrigins: ["sanctuary.isaacdelalama.dev"],
```

This is baked into the server build. A focused config test guards the
allowlist (`app/react-router.config.test.ts`).

## Verification

- `npm test` (105 tests), `npm run typecheck`, `npm run build` all pass.
- Local end-to-end: browser-like `https` Origin + valid review creds returned
  HTTP 202 with a session cookie; invalid creds returned the action's
  `Invalid username or password`; a spoofed `https://evil.example.com` Origin

- Production: a browser-like `https`-Origin POST now reaches the login action;
  a spoofed origin is still rejected.
