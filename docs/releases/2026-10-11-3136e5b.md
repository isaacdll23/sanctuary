## Why

The Assistant release (`dd9be26`) shipped web code whose schema was never
applied: `assistant_conversations` and `assistant_messages` did not exist in
production. The `migrate` service had reported success, but its logs showed
drizzle-kit aborting on an interactive prompt:

```
You're about to add finance_account_balance_snapshots_account_date_unique
unique constraint to the table, which contains 12 items. Do you want to
truncate the finance_account_balance_snapshots table?
Error: Interactive prompts require a TTY terminal ...
```

Two independent defects caused it:

1. **Truncated FK names.** Postgres truncates identifiers at 63 characters.
   Drizzle-kit auto-names foreign keys as
   `<table>_<column>_<reftable>_<refcol>_fk`, and three exceeded the limit
   (75, 64, 72 chars), so the database stored truncated names. drizzle-kit
   never matched them and dropped/re-added those FKs on every push.
2. **Composite unique constraint column order.** drizzle-kit's introspection
   returns composite unique constraints ordered by column name descending,
   while push diffs order-sensitively. The declared ascending order was
   therefore dropped and re-added on every push, and on a table with rows that
   re-add triggered the truncate prompt.

Because the prompt aborts the whole push, **no** migration was applied. And
because `drizzle-kit push` exits 0 even on that error, the container exited 0
and `release.sh verify` passed — the failure was invisible.

## Fix

- `app/db/schema.ts`: name the three long FKs explicitly
  (`fabs_account_id_fk`, `assistant_messages_conversation_id_fk`,
  `dpg_section_id_fk`) and declare the two composite unique constraints in the
  order drizzle-kit introspects (`balance_date, account_id` and
  `message_id, conversation_id`). A unique constraint is order-insensitive, so
  this only stops the spurious recreate; the physical index is untouched.
- `Dockerfile` (migrate target): fail the container on a non-zero exit **or**
  error output, since the exit code cannot be trusted.
- `scripts/release.sh`: verification now reads the migrate logs in addition to
  the exit code.
- `migrations/2026-10-11-assistant-conversations.sql`: aligned with the schema
  (explicit FK names, ascending index).

## Recovery applied during the incident

The missing tables were created by applying
`migrations/2026-10-11-assistant-conversations.sql` directly, and the four
drifted FK names were renamed to the explicit names so the fixed migrate is a
no-op. Downtime: web was stopped by the failed `sha-ff2bcd0` deploy attempt at
22:21 UTC and restored by this deploy at 22:27 UTC (~6 min).
